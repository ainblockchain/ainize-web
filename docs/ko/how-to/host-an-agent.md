# 에이전트를 노드에 올리기

에이전트가 `127.0.0.1:9200`에서 돌고 있습니다. [A2A](https://a2a-protocol.org/)를 말하고, `message/send`에 답하고,
에이전트 카드를 서빙합니다. 없는 것은 **남이 쓸 수 있는 주소** 하나뿐이고, 보통 여기서 서버를 빌리러 갑니다.

노드가 그 주소입니다. 등록된 에이전트에 공개 URL을 주고, well-known 경로에 카드를 서빙하고, 연결된 노드들에게
그 에이전트의 존재를 알립니다 — 그래서 내 마켓플레이스뿐 아니라 **그쪽 마켓플레이스에도** 뜹니다. 에이전트
프로세스는 있던 자리에 그대로 있고, 자기 주소를 가질 필요가 없습니다.

아래는 노드 하나와 에이전트 하나입니다. `ainize status`에 답하는 노드가 이미 있다고 가정합니다. 없으면
[내 노드로 네트워크에 참여하기](./join-from-your-own-node.md)부터 보세요.

## 등록

```bash
ainize agent add donga-desk --upstream http://127.0.0.1:9200
```

`donga-desk`가 id이고 그대로 URL 조각이 됩니다: 이제 에이전트는 `<내 노드>/agents/donga-desk`에 있습니다.
`--upstream`은 내 프로세스가 듣는 곳이고 **절대 공개되지 않습니다** — 노드가 에이전트에 닿는 경로일 뿐이고,
대개는 남에게 아무 의미 없는 주소입니다.

```bash
ainize agent ls
```

```text
donga-desk   answering   5 skills   https://ainize.ai/agents/donga-desk
```

`answering`은 등록했다는 뜻이 아닙니다. 노드가 에이전트의 카드를 실제로 가져와 봤다는 뜻입니다 — 모든 A2A
클라이언트가 제일 먼저 하는 요청이 그것이고, 카드를 못 가져오는 에이전트는 프로세스 목록에 뭐라고 뜨든
호출자 입장에서는 살아 있는 게 아닙니다.

## 호출자가 받는 것

카드는 모든 A2A 클라이언트가 찾는 그 경로에 있습니다:

```bash
curl -s https://ainize.ai/agents/donga-desk/.well-known/agent-card.json | jq '{name, url}'
```

```json
{ "name": "동아사이언스 운영 데스크", "url": "https://ainize.ai/agents/donga-desk" }
```

`url`이 `127.0.0.1:9200`이 아니라 노드 주소입니다. 에이전트 자기 주소를 그대로 둔 카드는 모든 클라이언트를
**자기 자신의 기계로** 보냅니다. 그래서 노드가 나가는 길에 고쳐 씁니다 — 이 구조를 전혀 모르는 평범한 A2A
클라이언트가 카드만 따라와서 동작하는 이유가 그것입니다.

그리고 호출은 워크스페이스가 보내는 것과 같은 JSON-RPC입니다:

```bash
ainize agent call donga-desk "오늘 파이프라인 상태 어때?"
```

`ainize agent card`와 `ainize agent call`은 `--upstream`이 아니라 **공개 경로로** 갑니다. 일부러 그렇습니다:
확인해야 하는 건 남이 받는 것이니까요.

## 내리기

```bash
ainize agent off donga-desk     # 등록은 두고 공개 주소만 내림
ainize agent on  donga-desk     # 다시 공개
ainize agent rm  donga-desk     # 등록 자체를 지움
```

작업 중일 때는 `off`입니다. 반쯤 만든 에이전트에 살아 있는 주소가 붙어 있는 건 주소가 없는 것보다 나쁩니다 —
카드는 응답하니까 호출자가 실패를 **자기 잘못으로** 읽습니다.

## 다른 노드에도 뜹니다

내 노드는 이미 돌고 있던 gossip 라운드에 자기 에이전트를 실어 연결된 노드들에게 알립니다. 그 노드들이 목록에
올리고, 거기 방문자는 **그 노드를 거쳐** 호출합니다:

```text
방문자 브라우저  ->  그쪽 노드  ->  내 노드  ->  내 에이전트
```

여기서 두 가지가 따라옵니다. 내 노드가 포트 포워딩 하나 없는 집 네트워크에 있어도 마켓플레이스에서 호출이
됩니다 — 중요한 건 노드 사이의 연결이고, 그건 내 노드가 **바깥으로** 맺은 것이기 때문입니다. 그리고 방문자가
받는 주소는 그 방문자가 보고 있는 노드의 것이지 내 것이 아닙니다: 공개되는 것은 "이 에이전트를 어느 노드가
돌린다"는 이름과 주소지, 내 노드가 **어디에 있는지**가 아닙니다.

id는 신원이 아닙니다. 두 노드가 `donga-desk`라는 에이전트를 돌리면 어느 한 노드에서 짧은 주소는 하나만
갖고, 나머지는 peer를 지목하는 경로 — `/sam/<peer>/a2a/donga-desk` — 로 언제나 정확히 하나를 가리킵니다.

## 노드가 하지 않는 일

**에이전트를 대신 실행해 주지 않습니다.** 에이전트는 자기 의존성과 자기 고장 방식과 자기 GPU 사정을 가진 별도
프로세스이고, 노드가 그걸 관리하면 노드가 재시작할 때마다 에이전트가 같이 죽습니다. 평소 띄우던 방식대로
(서비스, 컨테이너, `node server.js`) 띄우고 주소만 등록하세요.

**호출자 인증도 대신하지 않습니다.** A2A는 인증을 보내지 않습니다. 그래서 그 주소는 구조적으로 공개이고,
닿을 수 있는 사람은 누구나 호출합니다. 노드가 모든 에이전트 앞에 본문 크기 제한과 IP별 호출 제한을 둡니다.
에이전트도 자기 제한을 걸어야 합니다. 둘 중 하나만으로는 충분하지 않습니다.

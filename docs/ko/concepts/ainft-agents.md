# AINFT 호환 에이전트

중심 목표는 **Ainize 에이전트 → native AINFT → ain-wallet**입니다. Ainize에서 만든 에이전트가 AINFT와 호환되고 기존 지갑의 AINFT 목록·상세 화면에 표시되어야 합니다. 보유자는 에이전트를 열어 대화하고 일을 맡기며 함께 성장시킵니다. 기존 AINFT에 에이전트를 연결하는 것은 보조 경로입니다.

**2026년 10월 15일 운영 검증:** Ainize Node `7e4205a8ac0b`와 Web `f0de416922f7`를 운영 배포했습니다. prompt·tools·handler 실제 호스팅 에이전트 세 개에 기존 테스트넷 native AINFT를 재사용해 공개 메타데이터와 연결을 확인했습니다. 지갑 목록·상세에서 토큰을 표시하고 `https://ainize.ai/agent/<id>`를 직접 열어 실제 지갑 서명으로 로그인하고 작업을 완료했습니다. 실제 지갑 Send 화면으로 소유권을 바꾼 후 각 모드의 이전 소유자는 보유자 API 18개와 A2A 호출 4개 모두에서 차단됐습니다. 새 소유자 공간에는 이전 작업·기억이 없었고 새 작업을 완료하며 이전 작업을 조회할 수 없었습니다. 중복 민팅이나 메인넷 거래는 하지 않았습니다.

승인 기억은 이전 대화에 없는 새 사실로 검증했습니다. 후보 상태에서는 실제 답변에 나오지 않았고, 승인한 뒤 같은 질문에 그 사실이 반영됐습니다. 양도 후 새 소유자의 실제 답변에는 이전 소유자의 사실이 노출되지 않았습니다. 이 검증에는 모델 재학습을 사용하지 않았습니다. 지갑 PR #16으로 준비 요청 실패와 전송 결과 불명확 상태의 오류 처리를 수정했습니다. 준비 단계의 통제된 실패에서는 블록체인 전송 0건을 확인했고 이후 일반 지갑 양도가 성공했습니다. 지갑 2.3.0 패키지는 검증됐으며 Chrome 웹 스토어 업로드·배포는 남아 있습니다. 기존 스토어 2.2.0에서도 native 토큰 표시는 확인했지만 새 에이전트 직접 열기 링크는 없습니다. 아래 QA 보고는 과거 검증 이력입니다. 운영 Node의 테스트넷 전용 Factory 크레딧 연결에서도 작업 보상 세 건, 미사용 구매 환불, 실제 유료 작업과 이용권 정산을 확인했습니다. 개발 Factory와 별도 테스트 커뮤니티를 사용했으며 메인넷 크레딧 쓰기를 검증한 것은 아닙니다.

**상태 — 2026년 10월 11일:** 별도 QA에서 실제 테스트넷 native 민팅, 숫자 토큰 metadata 서비스, 에이전트 연결, Qwen 작업 완료와 승인한 비공개 기억의 대화 반영을 검증했습니다. 실제 지갑 SDK로 양도한 뒤 이전 보유자의 접근이 차단되고 새 보유자에게 별도 비공개 작업 공간이 제공됩니다. 현재 소스로 빌드한 ain-wallet 확장을 별도 Chromium에 설치해 새 보유자의 실제 토큰·이름·이미지·설명이 표시되고, 대화 버튼이 해당 토큰의 AINA 패널 경로를 선택하는 것을 확인했습니다. 암호화된 테스트 지갑의 실제 확장 서명 승인 화면으로 로그인했습니다. 보유자 화면에서 실제 작업 완료, 개인 기억 후보 저장·승인, 이후 모델 답변의 기억 반영도 확인했으며 NFT나 모델 응답을 대체하지 않았습니다. 소스로 실행한 AINA QA 패널에서 실제 Factory metadata를 조회해 원래 Ainize 에이전트를 열고 실제 지갑 서명으로 로그인했습니다. 브라우저 전송 프록시로 별도 QA 화면에 연결한 검증이며 운영 AINA 배포를 뜻하지 않습니다. AIN SSO 연결 없이 인증 완료 메시지를 위조한 뒤 브라우저 작업을 요청하면 차단됩니다. 기존 metadata 서비스가 ID를 숫자로 해석하므로 새 토큰에는 정확히 표현할 수 있는 정수 ID를 사용합니다. 개발 Factory의 실제 작업 보상, 미사용 구매 환불, 구매한 이용권으로 작업 실행과 재시작 후 정산을 검증했습니다. 운영 배포와 비공개 모델 학습·적용은 아직 미완료입니다. 지갑 서명으로 구매 내역 조회·구매·환불을 요청하는 클라이언트를 구현했으며 보유자 구매·환불 화면도 구현했습니다. 작업 실행 연결을 지원하는 서버에서만 새 구매를 활성화하며, 개발 환경에서 실제 구매·환불 화면과 Factory 보상·사용을 검증했습니다. 기본 브라우저 연결의 안정성과 운영 환경은 추가 검증이 필요합니다.

**추가 QA 검증:** 도구형·핸들러형 에이전트를 실제 native AINFT로 등록하고 작업을 완료한 뒤 새 소유자에게 양도했습니다. 이전 소유자는 HTTP 403으로 차단됐고, 새 소유자는 이전 작업이 없는 비공개 공간에서 새 작업을 완료했습니다. 새 소유자의 실제 ain-wallet 목록·상세에서 각 에이전트를 열고 완료 작업을 확인했습니다. 이 브라우저 검증은 실행 중인 AINA QA 프런트엔드 연결을 사용했고 HTTP/2를 진단 목적으로 비활성화했으며 Factory 응답은 직접 받았습니다. 운영 배포와 기본 브라우저 연결 안정성은 아직 입증되지 않았습니다.

성장은 보유자가 승인한 비공개 기억과 완료한 작업 이력을 이후 대화와 작업에 활용하는 방식으로 제공합니다. AINFT 호환·지갑 표시·소유자 접근에는 모델 재학습이 필요하지 않습니다. 별도 고급 모델 학습은 선택 기능이자 실험 단계이며 실패한 실험 결과는 적용하지 않았습니다. 핵심 보유자 기능의 배포 조건에 모델 재학습 성공을 포함하지 않습니다.

**운영 AINA 연결 검증:** PR #96을 병합하고 `9498cc40c1ae`로 운영 배포해 AIN SSO 확인 중이거나 연결할 수 없을 때도 공개 AINFT를 열 수 있도록 복구했습니다. 최종 지갑 PR #6 소스로 빌드한 확장에서 tools·handler 토큰 모두 운영 AINA의 공개 HTTPS로 올바른 QA 에이전트를 열고, 실제 지갑 서명으로 로그인하며 보유자의 완료 작업을 표시했습니다. AINA 화면 프록시·Factory 프록시·HTTP/2 변경 없이 검증했습니다. HTTP 401 리소스 오류 한 건이 있었지만 두 흐름 모두 완료됐습니다. 지갑 PR #6과 AIN Blockchain 안내 PR #12는 병합됐습니다. Chrome 웹 스토어 배포는 아직 확인하지 않았으며 Ainize 에이전트와 Factory 크레딧 확장은 QA·개발 환경입니다.

**별도 서빙 모델 검증:** 독립 GPU 모델에서 학습 결과 2,840개 행을 모두 적용해 비공개 모델의 답변이 바뀌고 동시에 요청한 공개 모델의 답변은 유지되는 것을 확인했습니다. 이후 2,840개 행을 모두 복원해 원래 답변으로 돌아왔고 복원 기록도 정상 해제됐습니다. 별도 QA 모델에서 실제 적용과 가역성을 검증한 결과입니다. 미학습 질문 평가에서 실패한 학습 결과의 채택 조건을 충족한 것은 아니며, 보유자가 시작하는 학습·평가·활성화 전체 검증은 남아 있습니다.

**실제 보유자 화면 복구:** 실제 Factory 예약을 성공시킨 뒤 성공 응답 한 번을 의도적으로 유실시켰습니다. QA 노드를 정상 설정으로 재시작한 후 현재 보유자가 실패한 작업의 복구 버튼을 눌러 이용권을 되돌렸습니다. 저장된 이용권 상태는 `reserving → restored`로 바뀌었고 작업 결과는 없었습니다. 응답 유실 검증 설정은 제거했으며 보호된 보상 설정도 유지됐습니다. 예약 성공 응답 유실 이후의 실제 보유자 화면 복구와 QA 노드 전체 재시작을 검증한 결과이며, 운영 배포는 아직 남아 있습니다.

## 현재 가능한 것

| 목적 | 기존 기능 | 추가 구현이 필요한 부분 |
|---|---|---|
| Ainize 에이전트를 ain-wallet에서 보기 | native AINFT object·민팅·metadata·지갑 계정 조회 | 에이전트의 토큰 등록과 지갑 검색 확인 |
| 캐릭터와 대화 | 서빙 중인 대화 모델과 프롬프트 에이전트 | 권한 있는 AINFT 캐릭터 설정 가져오기와 토큰 연결 |
| 일 맡기기 | 도구·핸들러 에이전트 | 토큰별 작업, 요청자 권한 확인, 비공개 결과 |
| 기존 AI 백엔드 유지 | 외부 A2A 에이전트 연결 | 다른 프로토콜을 쓰는 백엔드의 A2A 어댑터 |
| 에이전트 발견과 호출 | 에이전트 카드, 마켓플레이스, A2A 주소 | 프로필과 카드에 NFT 식별 정보 및 보유자 접근 정책 표시 |
| 함께 성장 | 지식 학습, 평가, 호환 런타임 적용 | 승인된 보유자 기억과 격리된 컬렉션 지식 |
| 커뮤니티 크레딧 적립·사용 | AINFT Factory의 credit·event·store 개념 | 검증된 기여 이벤트와 에이전트 혜택의 원자적 구매 처리 |

캐릭터 시제품은 [모델로 에이전트 만들기](../how-to/create-an-agent-from-a-model.md)를 이용합니다. 기존 A2A 백엔드는 [에이전트를 노드에 올리기](../how-to/host-an-agent.md)를 이용합니다. 이 과정은 에이전트를 생성하지만 NFT 소유권이나 보유자 제한을 설정하지는 않습니다.

## 구현할 보유자 사용 흐름

1. Ainize에서 프롬프트·도구·핸들러 방식으로 에이전트를 만듭니다. 기존 모델·코드·실행 주소를 유지하고 모든 방식에서 같은 AINFT 호환 metadata를 제공합니다.
2. 구현할 **AINFT로 등록** 흐름에서 지원 네트워크와 수신 지갑을 고르고 필요한 트랜잭션을 승인합니다. 등록된 native AINFT object를 만들거나 재사용하고 토큰 민팅·metadata 공개·계정 검색 반영을 확인합니다. 필요한 권한이 있는 기존 토큰을 연결할 수도 있습니다. 에이전트 페이지는 토큰·릴리스를 표시하고, 지갑은 토큰을 표시하며 에이전트 상세 페이지를 엽니다.
3. 비공개로 대화하거나 일을 맡깁니다. 실제 작업 상태·결과·오류를 보여주고 재시작 후에도 보존합니다. 대화에서 실행을 약속한 것은 도구 실행의 증거가 아닙니다.
4. 기억 후보의 내용을 검토하고 저장을 승인합니다. 보유자 개인 기억 또는 명시적으로 승인한 커뮤니티 기여를 선택합니다. 대화와 파일은 기본적으로 공개하지 않습니다.
5. 성장 근거, 업적, 커뮤니티 크레딧을 확인합니다. 컬렉션의 버전 있는 정책에 따라 완료한 작업 또는 승인한 기여에 보상하며, 중복 요청에는 중복 보상하지 않습니다.
6. 크레딧으로 작업 이용량이나 커뮤니티 기능 같은 공개된 혜택을 구매합니다. 구매 전에 비용, 제공할 권리와 환불 규칙을 보여줍니다.

이는 구현 목표이며, 지금 이용할 수 있는 NFT 조작 화면의 순서가 아닙니다. 등록은 별도로 승인하는 트랜잭션 흐름이며 에이전트 저장의 부수 효과가 아닙니다. 기존 AINFT를 연결할 때는 토큰과 metadata를 유지하고 재민팅하지 않습니다.

## 기존 ain-wallet과의 호환

지갑은 선택한 네트워크의 `nftServerUrl`에서 활성 지갑 계정의 토큰을 조회하고 `ainftObject.id`로 묶습니다. Ainize 에이전트 목록을 직접 읽지는 않습니다. 따라서 native AINFT 등록과 Factory 소유권 검색 반영이 필요합니다. 에이전트 카드나 NFT 모양의 JSON 내보내기만으로 지갑에 표시되지는 않습니다.

현재 설치된 지갑은 `nft.searchNfts({ userAddress, limit: 100 })`를 호출하고 `ainftObject.id`, `ainftObject.name`, `tokenId`, `tokenURI`, `metadata`가 있는 `nfts` 행을 읽습니다. 최신 SDK 문서에서 조회를 `searchAinfts`로 부르더라도 이 소비자 형식의 호환을 유지합니다. 첫 100개 뒤의 토큰도 발견할 수 있도록 페이지 처리를 지원합니다.

| 필드 또는 동작 | 요구사항 |
|---|---|
| `metadata.name` | 에이전트 표시 이름 |
| `metadata.description` | 공개 가능한 에이전트 소개 |
| `metadata.image` | 기존 지갑의 토큰 타일·상세 화면에서 읽을 공개 아바타 |
| `metadata.external_url`과 `ainize.detailUrl` | A2A 주소인 `/agents/<id>`가 아닌 사용자 화면 `/agent/<id>` |
| `metadata.ainize` | 버전 있는 에이전트 식별 정보·모델·릴리스·A2A URL·카드 URL·권한 및 성장 정책 |
| 네트워크와 수신자 | 일치하는 AIN 체인·RPC·NFT 서버와, SSO로 만든 에이전트의 명시적으로 확인한 수신 지갑 |
| 지갑에서 열기 | 안전한 HTTPS 에이전트 열기 동작. 잘못되거나 없는 확장 metadata는 기존 표시·Send를 방해하지 않음 |
| 양도 | 기존 native AINFT Send가 동작하고 소유권 검색 결과가 새 계정으로 이동 |

에이전트 준비 상태와 별도로 서명 대기·체인 확인·metadata 공개·Factory 검색 반영·지갑 표시의 등록 진행 상태를 보여줍니다. 실패한 등록을 재시도할 때 중복 민팅하거나 정상 에이전트를 삭제하지 않습니다. 개인키는 서명하는 지갑에 둡니다. 등록 완료에는 공개한 metadata를 다시 읽고 지갑과 같은 계정 조회로 토큰을 찾는 검증이 필요합니다.

기존 지갑은 이름·이미지·소개를 표시하고 Send를 제공합니다. 에이전트 열기와 native AINFT metadata 호환 처리는 지갑 PR #6에 구현·병합됐으며 최종 확장 빌드로 검증했습니다. Chrome 웹 스토어 배포는 아직 확인하지 않았습니다. 에이전트 metadata가 없는 기존 AINFT의 일반 표시와 전송 동작은 유지됩니다.

## 소유권과 권한

지갑 세션은 주소를 제어한다는 증거이고, 최신 체인 조회는 토큰을 소유한다는 증거입니다. 보유자 기능은 둘 다 요구하며, 소유권을 확인할 수 없으면 실행을 거절해야 합니다.

토큰 보유자, 컬렉션 관리자, 에이전트 운영자는 다른 역할입니다. 보유자는 보유자 기능을 사용하고, 컬렉션 관리자는 기존 규칙에 따라 metadata를 공개하며, 운영자는 코드와 배포를 관리합니다. 현재 호스팅 에이전트의 `owner`는 생성자입니다. 토큰 양도가 이를 자동으로 바꾸지는 않습니다.

**에이전트 공개 범위는 목록 노출을 제어하며 보유자 전용 실행 권한이 아닙니다.** 비공개 또는 링크만 공개한 주소도 보유자 권한 장치가 아닙니다. 연동은 웹 화면뿐 아니라 직접 A2A 호출, 스트리밍, 작업 조회, 다른 노드를 통한 호출에서도 소유권을 확인해야 합니다. 카드는 공개하면서 실행에 인증을 요구할 수 있습니다. 대기 중인 작업이 권한 있는 동작을 하거나 비공개 결과를 반환하기 전에도 소유권을 다시 확인합니다.

토큰이 양도되면 이전 보유자의 권한을 회수하고 새 보유자의 개인 작업 공간을 만듭니다. 토큰의 공개 업적은 유지할 수 있습니다. 이전 개인 대화, 개인 기억, 파일, 인증 정보, 지갑의 크레딧 잔액은 양도하지 않습니다. 컬렉션 공유 지식은 별도 공개 동의가 있는 다른 자료입니다.

## 직접 A2A 보유자 호출

로컬 native AINFT 연결이 완료되면 `/agents/<id>`에서 보유자 권한을 확인합니다. 공개 카드는 A2A 0.3과 `message/send`, `message/stream`, `tasks/get`, `tasks/cancel`을 안내합니다. 웹 작업 공간과 같은 지갑별 비공개 작업을 사용하며, 새 보유자가 이전 보유자의 작업 ID나 대화 문맥을 사용할 수 없습니다. 토큰 연결 후에는 일반 공개 에이전트 실행 경로 대신 보유자 전용 실행 경로를 사용합니다.

native 지갑 로그인 세션이나 매번 새로 서명한 `x-ainft-auth` 증명으로 인증합니다. 형식은 `<address>:<timestamp>:<signature>:v2`이며, core의 요청 결합 인증 형식에 목적 `ainft`, 대상 노드 주소, HTTP 메서드, 대상 경로, 시각과 정확히 직렬화한 본문을 포함해 서명합니다. 카드의 `urn:ainize:ainft-holder-auth:v1` 기능 확장이 대상 노드 정보를 제공합니다. 노드 간 중계도 이 증명을 전달하며, 중계 노드의 자체 서명은 보유자 권한이 아닙니다. 본문 변조, 잘못된 대상과 증명 재사용은 거절합니다.

스트림은 작업, 결과와 최종 상태를 전달하고 비공개 결과를 반환하기 전에 소유권을 다시 확인합니다. 대기 작업 취소는 실행을 막으며 이미 실행 중인 작업은 안전하게 취소됐다고 표시하지 않습니다. 현재 보유자는 비공개·조직 에이전트도 열 수 있지만 제작자의 프롬프트·코드·인증 정보 접근 권한을 얻지는 않습니다. 에이전트 버전이 바뀌면 토큰을 다시 민팅하지 않고 metadata와 연결을 갱신한 뒤 작업을 계속합니다.

## 기존 metadata를 유지하며 연결

AINFT의 specification은 캐릭터·모델·기능·에이전트 릴리스에, history는 승인된 결과와 기여 근거에, properties는 컬렉션 정책에 따른 레벨과 업적에 대응합니다.

추가로 제안하는 metadata 필드는 `ainize`이며 `schemaVersion`, `agentId`, `detailUrl`, `agentUrl`, `cardUrl`, `model`, `release`, `access`, `growthPolicy`를 담습니다. metadata 내보내기 API가 이 버전 확장을 생성하며, 에이전트 생성과 지갑 서명 기반 토큰 등록은 별도 단계입니다. 연결 기록은 토큰의 네트워크·컬렉션·토큰 ID도 식별해야 합니다.

metadata를 공개할 때 컬렉션의 기존 필드를 보존합니다. 기존 AINFT metadata 안내는 토큰 보유자와 다를 수 있는 object owner의 권한을 요구합니다. 트랜잭션을 확인하고 metadata를 다시 읽은 뒤 연결 완료로 표시합니다. 예시와 권한 규칙은 [AIN Blockchain 연동 명세](https://github.com/ainblockchain/docs/blob/main/ai-agents/ainft-agents.md)를 참고하세요.

## 개인 학습 예제 검토

보유자 공간의 승인된 기억 옆에서 **학습 예제 검토**를 선택합니다. 학습 질문(최대 400자), 답변(최대 200자), 같은 답변을 기대하는 다른 표현의 확인 질문(최대 400자)을 직접 검토하고 저장에 동의합니다. 확인 질문은 alt_prompt로 전달되며 학습에는 사용하지 않습니다. 함께 선택한 다른 학습 질문과도 달라야 합니다. 선택한 모든 예제에 확인 질문이 있어야 학습할 수 있고 확인 질문이 0개인 평가는 선택 조건을 충족하지 못합니다. 기존 예제는 계속 읽을 수 있으며 학습하려면 승인한 기억에서 새 예제를 검토해야 합니다. 예제는 해당 에이전트와 지갑의 개인 자료로 저장되고 재시작 후에도 유지되며 재시도해도 중복 생성되지 않습니다. 저장만으로 학습·공개·경험치·크레딧 지급을 실행하지 않습니다.

예제 사용을 철회하면 이후 학습 선택에서 제외합니다. 원본 기억의 승인을 철회하면 관련 예제도 모두 제외됩니다. 과거 대화 삭제나 이미 실행한 모델 학습의 취소를 의미하지 않습니다. 토큰을 양도받아도 이전 보유자의 예제를 볼 수 없습니다. 모델 개선에는 호환되는 학습·평가와 이후 대화에 사용할 평가된 학습의 명시적 선택이 필요합니다.

**모델 학습 상태 확인**에서 현재 로컬 런타임을 확인합니다. 에이전트가 실제 gradient 학습 런타임과 동일한 로컬 모델·서빙 주소를 사용할 때만 학습할 수 있습니다. 다른 노드의 모델·다른 백엔드·모의 학습 런타임은 거절합니다. 검토한 예제를 선택하고 학습 실행에 명시적으로 동의하면 질문·답변을 TeachWorker에 제출하고 작업 번호를 저장하며, 작업 상태는 해당 워커에서 읽습니다. 제출 응답을 잃으면 같은 요청을 다시 제출하지 않으며 운영자가 결과를 확인해야 합니다. 연결된 블록체인에는 지갑 주소·상태·자료 해시가 기록될 수 있지만 예제 내용이 자동 공개되지는 않습니다. 호스팅 대화는 같은 런타임 실행 잠금을 사용해 학습의 임시 평가가 끝날 때까지 기다립니다. 평가된 초안은 에이전트에 자동 활성화되지 않습니다. 활성 검토 예제로 만든 READY 작업에서 **이 학습 선택**을 누르고 변경 내용을 검토한 뒤 명시적으로 동의합니다. 이후 로컬 모델을 사용하는 보유자 대화마다 공유 런타임 잠금 안에서 선택한 학습을 적용하고, 응답이 끝나면 기록된 모든 모델 행을 이전 상태로 복원합니다. **기본 상태로 되돌리기**는 학습 기록과 승인한 기억을 유지하면서 선택한 학습의 사용을 중단합니다. 사용한 예제의 동의를 철회하거나 에이전트 릴리스가 바뀌면 선택은 무효가 되며 이전 학습을 자동으로 다시 사용하지 않습니다. 복원 기록이 없거나 복원에 실패하면 공유 모델의 새 대화를 차단하고 재시작 후에도 복원을 재시도합니다. 선택 이력은 지갑과 에이전트별 비공개 자료입니다. 호스팅 SDK의 모델 호출 경로를 사용하는 코드 에이전트에도 같은 소유자 전용 요청 범위를 전달합니다. 선택한 로컬 학습의 모델을 사용할 수 없으면 다른 노드의 모델로 대체하지 않고 요청을 거절합니다. 커뮤니티 크레딧 연동은 아직 미완성이며, 실제 모델 적용·복원은 배포 환경 검증이 필요합니다.

## 공유 공개 검토

실제 모델 평가와 원상복구 검증을 통과한 사용 가능한 READY 학습에서 **공유 공개 검토**를 선택합니다. 검증에 실패했거나 검증이 완료되지 않은 결과는 공유 공개도 할 수 없습니다. 이름과 설명을 검토하고 영구 공개와 공개 권리를 각각 확인합니다. 이 경로는 학습된 지식 파일을 CC-BY-4.0으로 무료 공개하며, 원본 예제는 비공개로 유지하고 수익 배분이나 크레딧은 지급하지 않습니다. 원본 예제가 비공개여도 공개 파일에는 학습한 내용이 포함되며 공개 후 회수는 보장되지 않습니다.

**지갑 서명 후 공개 요청**은 로그인한 보유자의 AIN Wallet에서 Teach 공개 확인문에 서명합니다. 제출 전에 지갑이나 로그인 상태가 바뀌면 요청을 거절합니다. Teach 서명 검증과 운영자 검토 정책은 그대로 적용합니다. 제출 후에도 운영자의 승인이 필요할 수 있으며 ANNOUNCED일 때만 공개 완료로 표시합니다. 제출 전에 의도를 저장하고 같은 학습 작업은 새 요청 키로도 다시 제출할 수 없습니다. 결과가 불확실하면 운영자가 확인해야 합니다.

## 성장에는 근거가 필요합니다

개인 대화 기록, 조회에 쓰는 기억, 학습한 모델 패치는 다른 것입니다. 메시지를 저장했다고 모델이 학습한 것은 아닙니다. 승인된 기억은 해당 보유자 범위에서 이후 답변에 영향을 주어야 합니다. 공유 학습은 평가를 통과하고 호환 런타임에 적용된 뒤 모델 개선으로 설명합니다. 학습이 실패하면 마지막 정상 릴리스를 유지합니다.

기존 학습 과정은 [파일로 가르치기](../tutorials/teach-from-a-file.md), 검증의 한계는 [검증 완료의 의미](./verification.md)를 참고하세요. [지식을 사서 기억하는 에이전트](../how-to/agent-memory.md)는 별도 기억 에이전트의 사용 흐름이며, 호스팅 AINFT 에이전트에 자동으로 기억을 제공하지 않습니다.

보유자 공간에서 `activity-v1` 규칙과 최근 성장 활동 기록 20개를 확인할 수 있습니다. 완료한 대화·작업과 처음 승인한 기억은 각각 경험치 1점을 기록합니다. 화면에 표시된 원본 작업과 기억은 기록에서 열 수 있습니다. 기억 승인을 철회해도 과거 활동 점수는 유지되며 기억은 사용 철회 상태로 표시됩니다. 기록은 재시작 후에도 에이전트와 지갑별로 비공개 유지됩니다.

경험치와 보상 정책에 버전을 붙입니다. 작업·기여의 고유 이벤트를 추적하고 각 이벤트에 최대 한 번 보상합니다. 레벨은 그 정책에 따른 활동 진척이며 답변 품질의 증명이 아닙니다.

## 크레딧과 실행 비용

현재 릴리스를 AINFT에 연결한 뒤, 제작자는 **커뮤니티 크레딧 연결**에서 기존 Factory 커뮤니티와 크레딧 기호를 지정하거나 연결을 해제할 수 있습니다. 설정은 버전 충돌을 확인하며 저장되고 AINFT 연결을 갱신해도 유지됩니다. 보유자 공간에서 연결된 Factory 사용자 ID를 입력하고 **지갑으로 잔액 확인**을 선택합니다. AIN Wallet 서명 한 번으로 보유자 전용 잔액 조회를 요청합니다. 기존 Factory 조회는 커뮤니티 관리자 서명이 필요하므로 일반 보유자가 사용할 수 없습니다. 새 보유자 조회 경로는 개발 Factory에 배포해 실제 지갑 서명으로 확인했습니다. Factory 서버가 잔액 조회 전후에 사용자의 기본 주소 또는 명시적으로 연결된 주소와 서명한 지갑의 일치를 확인합니다. 조회 전후에 현재 소유권을 확인하며 계정·네트워크·커뮤니티 설정이 바뀌면 결과를 표시하지 않습니다. 잔액 0은 유효하며 조회 실패와 잘못된 응답은 오류입니다. 잔액 조회와 구매 내역·구매·환불 화면을 구현했습니다. 작업 실행 연결이 준비되지 않은 서버에서는 새 구매를 비활성화합니다. QA 노드의 보상·작업 실행 연결과 실제 개발 Factory 환경 검증은 통과했습니다. 운영 배포는 아직 완료되지 않았습니다.

개발 Factory 확장에는 버전이 있는 혜택 정책, 고유 기여 이벤트 보상, 구매와 작업 이용권이 구현돼 있습니다. 기존 크레딧 잔액의 차감·대금 보관·구매 기록을 함께 저장합니다. 작업 시작 때 이용권을 예약하고 성공이 확인되면 정산하며, 확인된 실패는 이용권을 복원할 수 있습니다. 미사용 구매는 기록된 기간 안에 환불할 수 있습니다. 별도 Firebase 에뮬레이터에서 동시 요청·응답 유실·권한 검증을 확인했습니다. 개발 Factory에 배포했으며 현재 노드 소스에는 호스팅 작업 실행 연결을 구현했습니다. 로컬 구매·환불 화면은 서명 전에 구매 요청을 저장하고 새로고침 후에도 같은 요청을 유지합니다. 내역에서 정확히 일치하는 영수증을 확인해야 미확인 요청을 해제합니다. 서버가 작업 실행 지원을 확인한 경우에만 새 구매가 활성화됩니다. 실제 개발 환경의 화면·Factory 보상·환불·작업 이용권 정산 검증은 통과했습니다. 실제 Factory 응답만 유실시킨 엔진 검증에서도 작업 실행 없이 이용권을 복구했으며, 해당 오류 복구의 사용자 화면 검증은 남아 있습니다.

Factory 커뮤니티 크레딧, AIN, x402 결제, 학습·GPU 예산은 다른 단위입니다. 토큰 보유나 크레딧 적립만으로 추론과 학습이 무료가 되지는 않습니다. 컬렉션은 구매한 혜택의 실행 비용을 부담하는 방법을 정해야 합니다.

보상에는 인증된 근거와 고유 이벤트 ID가 필요합니다. 구매에는 원자적인 잔액 확인·차감, 제공할 권리와 환불 규칙이 필요합니다. 재시도할 때 보상을 중복 지급하거나 두 번 차감하지 않습니다. 기존 [결제](./payment.md) 기능이 자동으로 Factory 크레딧을 연결하지는 않습니다.

## 출시 전에 통과해야 할 조건

먼저 Ainize의 각 호스팅 방식으로 에이전트를 만들고 native AINFT로 등록한 다음, 기존 지갑에서 목록 조회·metadata 표시·에이전트 열기·다른 계정으로 Send를 검증합니다. 새 보유자의 검색과 이전 보유자의 권한 회수도 확인합니다. ERC721 검증으로 이 native 지갑 검증을 대체하지 않습니다. native AINFT와 ERC721 모두 기존 metadata를 유지하며 연결해야 합니다. 보유자 대화와 실제 작업이 동작하고 재시작 후에도 보존되어야 합니다. 모든 실행 경로에서 비보유자를 거절해야 합니다. 양도 시 개인 자료 유출 없이 이전 보유자 권한을 회수해야 합니다. 승인된 기억이 올바른 범위의 이후 답변에 반영되고, 공유 학습은 활성화 전에 평가해야 합니다. 성장·크레딧 이벤트는 재시도에 안전하고 구매는 원자적이어야 합니다. metadata와 에이전트 페이지의 토큰·릴리스가 일치해야 합니다. 웹 화면에서 연결·권한·대화·작업·기억 승인·성장·크레딧과 정확한 오류 상태를 제공해야 합니다.

이 검증을 통과하기 전에는 캐릭터 시제품을 일반 Ainize 에이전트로 취급하며, 보유자가 제어하는 완성된 AINFT 에이전트로 표시하지 않습니다.

`ainize-web-unified/scripts/ainft-testnet-qa.ts`의 명시적으로 실행하는 네이티브 테스트넷 등록 도구에는 실제 공개된 `/agent/<id>` 주소인 `AINFT_LIVE_AGENT_URL`, 비공개 테스트 지갑 파일인 `AINFT_LIVE_IDENTITY_FILE`, 설치된 AIN SDK 경로인 `AINFT_LIVE_SDK_PATH`가 필요합니다. 실제 metadata와 에이전트 카드의 릴리스·접속 주소를 확인하고, metadata를 재시도 안전한 등록 상태와 함께 고정합니다. 저장된 에이전트가 다르거나 metadata가 바뀌면 중단합니다. 연결·지갑 표시·양도는 각각 별도 확인 전까지 미검증으로 기록됩니다. 이 도구는 임시 에이전트를 만들거나 전체 보유자 경험의 완료를 증명하지 않습니다.

### 현재 소스의 크레딧 통합

운영자가 `AINFT_REWARD_CONFIG_FILE`을 지정하면 노드가 보상 전송부와 이용권 작업 엔진을 연결합니다. 설정과 서명 키는 에이전트 데이터 밖에 있는 소유자 전용 일반 파일이어야 합니다. 에이전트 metadata로 운영 키나 권한을 지정할 수 없습니다. 보유자는 `POST /api/hosted-agents/{id}/companion/credits/enroll`로 Factory 계정을 연결합니다. 활성 정책·지갑 연결·현재 NFT 소유권·변경되지 않은 연결 설정을 확인합니다. `GET .../credits/rewards`는 현재 보유자에게만 지급 상태를 제공합니다. 완료 작업과 첫 기억 승인에 보상 요청을 함께 저장하고, 정책 버전과 이벤트 ID를 유지해 응답 유실 후 재시도합니다. 릴리스나 커뮤니티가 바뀌면 예전 등록으로 새 보상을 만들지 않습니다.

보유자 화면에 보상 연결·지급 상태·구매 내역·구매와 환불·이용권 선택을 구현했습니다. 새 구매에는 서버가 허용한 현재 정책이 필요하며 기존 구매는 구매 당시 정책 버전을 유지합니다. 이용권 작업 요청은 `purchaseId`와 `purchasePolicyVersion`을 포함합니다. 제출 전에 요청 키를 저장하되 개인 요청 원문은 저장하지 않으며, 일치하는 작업 응답을 확인해야 키를 해제합니다. 노드는 이용권을 예약한 뒤 에이전트를 실행하고 결과를 저장한 뒤 정산합니다. 정산이 대기 중이어도 완료 결과를 유지합니다. `POST .../tasks/{taskId}/settlement`는 작업을 재실행하지 않고 정산만 재시도합니다. 실행 중 중단된 작업은 자동 재실행하거나 이용권을 복원하지 않습니다.

2026년 10월 11일 별도 Ainize QA 에이전트에 보호된 운영 설정과 개발 Factory 연결을 배포했습니다. 실제 제작자·보유자 서명으로 커뮤니티 설정과 보상 등록을 완료했고, 새 작업 세 건에 각각 1크레딧을 지급했습니다. 보유자 서명으로 2.5크레딧에 작업 2회분을 구매하고 미사용 구매를 환불했으며, 다시 구매한 이용권으로 실제 모델 작업을 완료하고 정산했습니다. 실제 Factory 응답을 전달하는 검증 경로에서 잔액·구매 내역·남은 사용량 표시도 확인했습니다. HTTP/2를 끈 브라우저 비교 실행에서는 Factory 직접 연결도 통과했으며 기본 전송 설정의 연결 오류는 추가 조사 중입니다. 다른 호스팅 방식, 비공개 모델 학습·적용과 운영 배포는 아직 검증이 남아 있습니다.


### 현재 소스의 이용권 복구

보유자 작업 공간은 유료 작업의 이용권 상태와 복구·정산 가능 여부를 제공합니다. 화면에서 실행 전에 멈춘 작업은 **예약 사용량 복구**, 완료 후 정산 확인이 남은 작업은 **정산 확인 재시도**를 선택할 수 있습니다. `POST .../tasks/{taskId}/allowance/restore`는 예약 응답이 유실돼도 원래 작업 식별자로 예약을 확인하고 작업을 실행하지 않은 채 사용량을 복구합니다. 복구 응답 유실도 같은 요청으로 재시도할 수 있습니다. 이미 실행했거나 실행 결과가 불확실한 작업은 복구를 거부하며 운영자 확인이 필요합니다. ainize SSH 서버에서 관련 테스트 10개와 노드·웹 빌드가 통과했습니다. 별도 Factory QA 이미지도 현재 개발 런타임에서 빌드됐고, 네트워크를 차단한 상태에서 크레딧·지갑 서명 테스트 파일 두 개가 통과했습니다. 별도 실제 개발 환경의 크레딧 검증 결과는 위에 기록했으며 운영 배포는 아직 검증되지 않았습니다.

### 10월 12일 검증 상태

Factory 확장과 서명 누락 처리 수정은 10월 11일 운영 서버에도 배포됐습니다. 상태 조회 HTTP 200, 서명 없는 보호 요청 HTTP 401을 확인했으며 운영 크레딧 쓰기는 실행하지 않았습니다. 버전 이미지가 서버에 저장돼 있지만 레지스트리 인증을 사용할 수 없어 이미지 업로드는 남아 있습니다. 위의 개발 환경 검증은 운영 크레딧 거래 검증을 대신하지 않으며 노드·웹 운영 반영은 별도로 남아 있습니다.

### 공식 배포 지갑 표시 검증

10월 12일에는 Chrome 웹 스토어의 AIN Wallet 2.2.0 파일을 변경 없이 실행해, 실제 테스트넷 수신자의 Ainize 컬렉션과 AINFT Companion QA 토큰의 이름·설명·탐색기 링크·Send 버튼을 확인했습니다. Factory 응답을 직접 받았고 모의 데이터나 브라우저 전송 설정 변경을 사용하지 않았습니다. 해당 토큰의 기존 지갑 표시 호환성은 검증됐습니다. 공식 배포본에는 기존 AI Editor 버튼이 있으며 새 직접 대화 버튼의 공식 배포는 아직 확인되지 않았습니다.
